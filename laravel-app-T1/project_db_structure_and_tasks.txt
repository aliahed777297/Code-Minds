
مقدمة
- هذا الملف يشرح كيفية ربط قاعدة البيانات بمشروع Laravel الموجود، خطوات التشغيل الأساسية، هيكلية المشروع، ثم تقسيم عمل الواجهات وملفات CSS/DB بين أعضاء الفريق الخمسة.
دليل ربط قواعد البيانات وهيكل المشروع وتوزيع المهام للفريق

1) إعداد قاعدة البيانات وربطها بالمشروع
- إنشاء قاعدة بيانات جديدة (مثال: `laravel_app_t1`) على MySQL أو MariaDB.
- في ملف `.env` (أو إنشاء نسخة من `.env.example`) ضع الإعدادات التالية:
  DB_CONNECTION=mysql
  DB_HOST=127.0.0.1
  DB_PORT=3306
  DB_DATABASE=laravel_app_t1
  DB_USERNAME=اسم_المستخدم
  DB_PASSWORD=كلمة_المرور
- تثبيت التبعيات: تشغيل `composer install`، ثم `npm install` (أو `pnpm`/`yarn`) إذا لزم الأمر.
- توليد مفتاح التطبيق: `php artisan key:generate`.
- تشغيل المايجريشنز: `php artisan migrate`.
- تشغيل الـ seeders (إن وُجدت): `php artisan db:seed` أو `php artisan db:seed --class=ServiceSeeder`.
- إن كانت هناك مشكلة في الاتصال: راجع `config/database.php` وتأكد أن إعدادات `.env` صحيحة.

2) ملفات المايجريشن والبيانات الموجودة في المشروع (مهمة للمراجعة)
- ملفات المايجريشن في `database/migrations/`:
  - 2025_12_28_000001_create_services_table.php
  - 2025_12_28_000002_create_cart_items_table.php
  - 2025_12_28_000003_create_orders_table.php
  - 2025_12_28_000004_create_order_items_table.php
  - 2025_12_29_000005_create_contact_messages_table.php
  - وغيرها (users, jobs, cache...) 
- تأكد من وجود seeders: `DatabaseSeeder.php`, `OrderSeeder.php`, `ServiceSeeder.php`.

3) هيكلية عمل المشروع (موجز)
- `app/Models/` يحتوي النماذج الأساسية: `Service`, `Order`, `OrderItem`, `CartItem`, `ContactMessage`, `User`.
- `app/Http/Controllers/` يحتوي الكنتـролرز التي تتحكم بالمنطق (مثال: `ServiceController.php`).
- `resources/views/` يحتوي واجهات blade: مجلدات `about`, `cart`, `contact`, `home`, `invoice`, `layout`, `order`, `services`.
- `public/css/` فيه ملفات CSS لكل صفحة (about.css, cart.css, contact.css, global.css, header.css, home.css, invoice.css, order.css).
- العلاقات الأساسية بين النماذج:
  - `Order` 1--* `OrderItem` (طلب يحتوي عناصر)
  - `User` 1--* `Order`
  - `Service` قد يُستخدم كمنتج/خدمة تظهر في الصفحة `services`
  - `CartItem` يرتبط مؤقتًا بـ `User` أو جلسة المستخدم

4) تقسيم العمل بين أعضاء الفريق (خمسة مبرمجين)
ملاحظة عامة عن طريقة العمل: كل عضو يعمل على فرع feature خاص به، التسمية المقترحة: `feature/<اسم>-<وصف>`، ثم رفع PR إلى `main` بعد المراجعة.

- زياد الشاوش — واجهات وخدمات الـ Services (Frontend + ربط مع Model)
  - المسؤوليات:
    - صفحة عرض الخدمات: ملفات Blade داخل `resources/views/services/`.
    - التعديل على `ServiceController.php` (أو إنشاء موارد API إذا لزم).
    - تعديل/مراجعة `app/Models/Service.php` وإضافة العلاقات والـ scopes اللازمة.
    - CSS/JS المتعلقة: `public/css/home.css` (إن عرض الخدمات من الصفحة الرئيسية) و/أو إضافة `public/css/services.css` (إن لم تكن موجودة فعلاً).
  - الملفات المتوقعة للعمل عليها:
    - `app/Http/Controllers/ServiceController.php`
    - `app/Models/Service.php`
    - `resources/views/services/*` (index, show, partials)
    - `public/css/home.css` أو `public/css/services.css`

- علي العدله — سلة التسوق (Cart) وواجهة المستخدم للتعامل مع عناصر السلة
  - المسؤوليات:
    - صفحات `cart` في `resources/views/cart/` وإجراءات الإضافة/الحذف.
    - منطق `CartItem` في `app/Models/CartItem.php` والتفاعل مع الجلسة/المستخدم.
    - ربط واجهة السلة مع `Order` لإنشاء طلب عند الشراء.
    - CSS المرتبط: `public/css/cart.css` و`public/css/header.css` (إن لزم).
  - الملفات المتوقعة للعمل عليها:
    - `app/Models/CartItem.php`
    - `resources/views/cart/*`
    - `public/css/cart.css`
    - أي تغييرات في Routes (`routes/web.php`) أو Controller جديد/تعديل للحالة

- محمد الشميري — صفحة الطلبات والفوترة (Orders & Invoice)
  - المسؤوليات:
    - صفحات إنشاء الطلبات وعرض الفواتير في `resources/views/order/` و`resources/views/invoice/`.
    - `app/Models/Order.php`, `app/Models/OrderItem.php` وإضافة العلاقات والـ accessors المطلوبة.
    - منطق حفظ الطلب في `OrderController` (إن لم يوجد، إنشاؤه).
    - CSS: `public/css/order.css`, `public/css/invoice.css`.
  - الملفات المتوقعة للعمل عليها:
    - `app/Models/Order.php`, `app/Models/OrderItem.php`
    - `resources/views/order/*`, `resources/views/invoice/*`
    - `public/css/order.css`, `public/css/invoice.css`

- زياد الرجوي — نموذج الاتصال (Contact) وواجهة المستخدم المتعلقة به
  - المسؤوليات:
    - صفحات `resources/views/contact/` ونموذج الإرسال.
    - `app/Models/ContactMessage.php` وتخزين الرسائل في القاعدة.
    - `ContactController` (إن لم يكن موجودًا إنشاؤه) لمعالجة الحفظ والردود.
    - CSS: `public/css/contact.css`.
  - الملفات المتوقعة للعمل عليها:
    - `app/Models/ContactMessage.php`
    - `resources/views/contact/*`
    - `public/css/contact.css`

- امين القحطاني — التنسيق العام (Layout, Header, Global CSS) وربط الواجهات
  - المسؤوليات:
    - تحسين `resources/views/layout/` (الـ master blade, header, footer, partials).
    - إدارة `public/css/global.css` و`public/css/header.css` لضمان تناسق المظهر عبر الصفحات.
    - مراجعة توافق الـ CSS مع الصفحات الأخرى وتقديم تعديلات صغيرة عند الحاجة.
  - الملفات المتوقعة للعمل عليها:
    - `resources/views/layout/*`
    - `public/css/global.css`, `public/css/header.css`

5) توجيهات عملية لكل عضو عند العمل على ملف/مهمة
- أنشئ فرعًا جديدًا من `main`: `git checkout -b feature/<اسم>-<المهمة>`.
- التزام تغييرات صغيرة ومبسطة: `git add .` ثم `git commit -m "شرح مختصر للتغيير"`.
- رفع الفرع إلى الـ remote: `git push origin feature/<...>`.
- افتح Pull Request واطلب مراجعة من زميلين على الأقل قبل الدمج.
- عند الحاجة لتغييرات بالـ DB (مايجريشن جديد): اذكر اسم المايجريشن والسبب في الـ PR، وضمّن أمر التشغيل للمراجعين (`php artisan migrate`).

6) خطوات تشغيل سريعة للمُراجعين أو المطور المحلي
- تثبيت الحزم: `composer install`
- إعداد `.env` بنسخة من `.env.example` وتعديل إعدادات DB.
- توليد مفتاح: `php artisan key:generate`
- تشغيل المايجريشن: `php artisan migrate`
- تشغيل السيرفر محليًا: `php artisan serve` ثم فتح `http://127.0.0.1:8000`.

7) ملاحظات إضافية
- إذا أردتم واجهة API منفصلة: أنشئوا `api` routes في `routes/api.php` وكنترولرز Resources.
- توثيق أي تغيير بنيوي (DB schema أو أسماء الحقول) داخل وصف الـ PR لتسهيل المراجعة.
- عند رفع المشروع على GitHub، اجعلوا ملف هذا الدليل في الجذر ليكون مرجعًا للفريق.

خاتمة
- الملف الآن يصف كيف يتم ربط DB بالمشروع، هيكل المشروع، وتقسيم عمل الفريق مع الملفات المحددة لكل واحد. اتبعوا قواعد الـ git الموضوعة لفروع الـ features وPRs.

8) خطوات تشغيل المشروع عند أول تنزيل (For first-time setup)
- المتطلبات المسبقة (تأكد منها قبل البدء):
  - XAMPP/Apache + MySQL مُشغلان
  - PHP (متوافق مع إصدار Laravel المستخدم)
  - Composer مثبت
  - Node.js و npm مثبتان إن أردتم بناء الأصول

- خطوات النسخ والتشغيل (Windows / PowerShell)، نفّذها من جذر المشروع بعد استنساخه:
  1. استنساخ المستودع وفتح المجلد:
```powershell
git clone <repo-url> laravel-app-T1
cd laravel-app-T1
```
  2. إنشاء ملف البيئة ونسخ المتغيرات الافتراضية:
```powershell
copy .env.example .env
# أو PowerShell: cp .env.example .env
```
  3. تثبيت تبعيات PHP وNode:
```powershell
composer install
npm install
```
  4. توليد مفتاح التطبيق:
```powershell
php artisan key:generate
```
  5. إنشاء قاعدة البيانات في XAMPP (phpMyAdmin) باسم `project_one` أو الاسم المتفق عليه.
     - بدلاً من ذلك يمكن تشغيل MySQL CLI:
```sql
CREATE DATABASE project_one CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```
  6. تعديل إعدادات الاتصال في ملف ` .env` ليتطابق مع XAMPP (مثال):
```
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=project_one
DB_USERNAME=root
DB_PASSWORD=
```
  7. تنظيف كاش إعدادات الكونفيج (بعد تعديل `.env`):
```powershell
php artisan config:clear
php artisan cache:clear
```
  8. إنشاء جدول الجلسات (إن لم يكن موجودًا بالفعل) ثم تشغيل المايجريشنز:
```powershell
php artisan session:table

```
  9. تشغيل الـ seeders إن وُجدت (اختياري):
```powershell
php artisan db:seed
```
  10. ربط مجلد التخزين العام (لملفات التحميل):
```powershell
php artisan storage:link
```
  11. تشغيل بيئة التطوير للـ assets ثم تشغيل السيرفر:
```powershell
npm run dev   # أو npm run build للإصدار
php artisan serve
# ثم افتح http://127.0.0.1:8000
```

- ملاحظات ونصائح عملية:
  - إن أردتم استخدام Virtual Host في XAMPP: أضيفوا ملف vhost واسمّوا المشروع، ثم أعدوا تشغيل Apache.
  - إذا صادفكم خطأ في صلاحيات الملفات على `storage` أو `bootstrap/cache` نفّذوا:
```powershell
icacls storage /grant "%USERNAME%":(OI)(CI)F /T
icacls bootstrap\cache /grant "%USERNAME%":(OI)(CI)F /T
```
  - لتشغيل الاختبارات: `php artisan test`.

خاتمة
- بعد إتمام هذه الخطوات سيعمل التطبيق محليًا متصلًا بقاعدة بيانات MySQL في XAMPP، ويمكن لكل عضو اتباع نفس الخطوات عند استنساخ المشروع لأول مرة.
